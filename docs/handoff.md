# Передача проекта между ПК и сессиями

## Минимальная команда для нового Codex

`Прочитай AGENTS.md, STATUS.md, PLAN.md и docs/variant.md. Проверь git status и продолжи с ближайшего незавершенного пункта, не запуская автоматизацию Multisim.`

## Протокол начала работы

Актуальное уточнение 06.09.2026: Word — 28 страниц, рисунки до 2.23. Пользователь выбрал остановку на 6, а не непрерывный цикл. Рисунок 2.11 исправлен на один XLA. Руководство сборки — `docs/multisim_22_23.md`; расчётные картинки — `deliverables/figures_aligned/`. В Multisim новые блоки ещё не проверены. Старые рисунки 2.14–2.16 в `figures_22_23` относятся к прежней версии, не брать их за актуальную нумерацию.

1. Убедиться, что открыта корневая папка репозитория.
2. Выполнить `git status --short --branch`.
3. Прочитать актуальный результат из `deliverables/` и статус.
4. Не трогать незакоммиченные пользовательские изменения.
5. Выбрать один ограниченный этап из `PLAN.md`.

## Протокол завершения этапа

1. Проверить расчеты или визуально проверить измененный документ.
2. Обновить `STATUS.md`: что закончено, что осталось, ближайший следующий шаг.
3. Добавить датированную запись в `CHANGELOG.md`.
4. Обновить чекбоксы в `PLAN.md`.
5. Проверить `git diff` и `git status`.
6. Создать коммит с понятным сообщением.

## Правило версий Word

- Текущая версия всегда находится по пути `deliverables/Курсовая_Блинов_текущая.docx`.
- Перед рискованной крупной переработкой можно создать архивную копию с датой, но не плодить версии после каждого мелкого исправления.
- После редактирования DOCX требуется полный постраничный рендер и визуальная проверка.

## Что передавать

Для другого ПК достаточно всего Git-репозитория. Временную папку `_docx_work/` переносить не нужно: она исключена из Git и может быть создана заново.
